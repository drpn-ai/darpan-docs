---
title: "Manage tenant settings"
description: "Set the shared tenant timezone, register the Google Chat or Slack spaces runs report to, and find peak periods and the sync pulse."
---

Two settings define how your tenant behaves for everyone on it: the shared timezone and the chat spaces runs report to. Neither takes long to configure — but getting both right before your first automated run saves your team from reading timestamps in the wrong zone and having to open the app to find out whether a sync failed. Tenant Settings also opens peak periods and the sync pulse, and the Notifications page holds the streaks space.

<Note>
Confirm the active tenant before saving. Tenant settings apply to the selected tenant, not every tenant you can access.
</Note>

## Before you start

Confirm:

- You are signed in as a Tenant Admin for the tenant you want to manage.
- The active tenant named on **User Settings** is correct.
- The tenant timezone is known.
- For each space you intend to register: a Google Chat incoming webhook, or a Slack workspace you can connect.

## What Tenant Settings controls

The page opens with the tenant's name and two facts; choose a fact to change it. Below them, **Schedule** holds two rows; choose a row to open its page.

| Where | Setting | Use it for | Tenant Admin access |
| --- | --- | --- | --- |
| Header | **Timezone** | The tenant's default date and time interpretation for workflows, schedules, and date windows. | View and edit |
| Header | **Notifications** | The named Google Chat or Slack spaces runs report to, and what posts to each, including streaks. | View and edit |
| **Schedule** | **Peak periods** | Busy days that move runs, hold them out of peak hours, and limit Darpan's HotWax and NetSuite reads. The row names the period on now, or the next one and when it starts. See [Peak periods and sync pulse](/guides/peak-periods-and-sync-pulse). | View and edit |
| **Schedule** | **Sync pulse** | Daily checks whose HotWax orders are watched every few hours, with a time an order may wait. The row counts the pairs that pulse. See [Peak periods and sync pulse](/guides/peak-periods-and-sync-pulse#watch-orders-with-a-sync-pulse). | View and edit |

## Steps

<Steps>
<Step title="Confirm the tenant context">

Open **Ask Darpan**. Search for **Open User Settings**.

At the top of the page, under your name, confirm the active tenant. If the wrong tenant is active, choose **Switch** before continuing.

</Step>
<Step title="Open Tenant Settings">

Open **Ask Darpan** again. Search for **Open Tenant Settings** and open the result.

</Step>
<Step title="Set the timezone">

Choose **Timezone** in the header.

Select the timezone for the tenant and save. Use the timezone that operators expect for schedules, date windows, and review timestamps.

The tenant timezone leads: when it is set, everyone on the tenant sees times in it, whatever their personal setting. See [Timezones and how dates resolve](#timezones-and-how-dates-resolve) below.

Changing it does not move existing automations. Each automation keeps the zone it was saved with; see [Set up an automation](/guides/setup-automation#timezone). An audit with no zone of its own is different: it uses the tenant's zone for its schedule and its day window.

</Step>
<Step title="Register chat spaces">

Choose **Notifications** in the header.

The page is a grid. Each column is a chat space, with its chat product (Google Chat or Slack); each row is something that posts, and its dot marks the space it posts to. Choose **Add space** and answer one question per card. For **A Slack channel**, pick the channel. For **A Google Chat space**, paste its webhook URL and give it a name that is unique within the tenant. Darpan validates a webhook URL on save, and the last cards let you pick what posts to the new space and **Send test**.

<Warning>
Webhook URLs are stored in clear text and returned to members of the tenant who can read its chat spaces. Anyone holding the URL can post into the space. If one leaks, create a new webhook in the chat product and update the space.
</Warning>

Automations link to a space, and individual users pick one of these spaces as their personal default. The same spaces receive an audit's update after each run, a scheduled query's summary, and streaks.

To choose where tenant-wide streak messages go, set the dot on the **Streaks** row to a space, or to **Nowhere** to send none. A streak one automation earns posts to that automation's own space. For the end-to-end alert flow, see [Run-completion alerts](/guides/run-completion-alerts).

</Step>
<Step title="Verify the change">

Return to **Open Tenant Settings** and confirm the timezone, and open **Notifications** to confirm the registered spaces. For notification changes, run a small saved reconciliation or automation test when the team needs proof that messages are delivered.

</Step>
</Steps>

## Timezones and how dates resolve

Darpan resolves the timezone it displays and calculates in from the first of these that is set:

1. The tenant timezone, from **Tenant Settings** > **Time**.
2. The signed-in user's timezone, from **User Settings**.
3. The server default (UTC unless the deployment sets one).

The tenant leads because reconciliation dates describe the tenant's business day, so everyone on a tenant reads the same day boundaries. A personal timezone in **User Settings** applies only while the tenant has none set.

This affects more than formatting. Run date windows and API day ranges are anchored to midnight in the resolved timezone. Set the tenant timezone to the one your operations actually run on.

Scheduled automations are the exception: each one runs in its own saved zone. See [Set up an automation](/guides/setup-automation#timezone). An audit with no zone of its own runs in the tenant's zone; see [Audits](/guides/audits#audit-settings).

Times in the app carry no zone code. Rest on one and Tara names its zone and offset. A run's date window is shown in the zone the run was anchored in, which can differ from the resolved zone above, and Tara gives the exact instants the run covered.

## Config history

Config history lists versions of the tenant's audit config, every audit together. Open it from an audit's settings: the clock beside the back arrow. It is not on Tenant Settings, since a tenant with no audits has nothing to version. A version is kept a minute after an audit, check, run or connection changes. **Keep a version now** saves one at once.

Choose an older version to **Restore** it. Restoring and keeping a version need tenant edit access; others can read the list.

## Queries

Queries have their own page since 3.4.3: **Queries** on the Dashboard, or in Cmd+K. A query is a read over what the tenant's audits keep and a JEXL script that answers a question, which a schedule can email every day. Tenant scripts became queries in 3.4.0. See [Queries](/guides/queries).

## Share a source configuration with another tenant

Sharing is set on the connection itself, not in Tenant Settings. Open the Shopify, HotWax, or NetSuite configuration and use its **Shared with** panel. See [Set up Shopify](/guides/setup-shopify#share-the-connection-with-another-tenant).

## Troubleshooting

| Symptom | What to check |
| --- | --- |
| You cannot save tenant settings | Confirm you are a Tenant Admin for the active tenant. Tenant Users can view tenant data and run reconciliation but cannot edit tenant settings. |
| The wrong tenant changed | Switch to the intended tenant from **User Settings**, then review **Open Tenant Settings** again. |
| A space is registered but no message arrives | Confirm the space is active and still has a webhook, and that an automation is linked to it or someone subscribed with **Notify me**. Registering a space does not by itself route any run to it. |
| A space cannot be deleted | An automation, a query schedule or an active run subscription still references it. Deactivate it instead. |
| Timestamps differ between two people on the same tenant | The tenant has no timezone set, so each person's **User Settings** timezone applies. Set the tenant timezone. |
