NetSuite involves more moving parts than most connections: account IDs, role permissions, integration records, certificates. Confirming these with the NetSuite owner before you start means a failure gives you a useful error instead of a dead end.

<Note>
Runs read NetSuite over SuiteQL with an **OAuth2 M2M JWT** auth profile. A [lifecycle](/guides/lifecycle-runs) reads the account directly: you pick the account and Darpan builds its queries. A Sync run reads NetSuite through a saved NetSuite check, which defines the records to read. The app has no screen for creating checks; they are saved through the API (`facade.NetSuiteQueryFacadeServices.save#NsSuiteQlSourceQuery`). Otherwise, export the data and use a **File upload** source when you [set up a reconciliation run](/guides/setup-reconciliation-run).
</Note>

## Before you start

Confirm:

- You are a Tenant Admin, or have edit access, for the active tenant.
- The NetSuite owner has given you the authentication method and its values: a username and password, a token, or an OAuth 2.0 client-credentials setup (client ID, certificate ID, and private key).
- For OAuth 2.0, the integration record and role in NetSuite grant the permissions the account needs.

## Open NetSuite settings

From **Ask Darpan**, open **Open NetSuite Settings**. The page has two sections:

- **Auth**: authentication profiles. **Create Auth Profile** adds one.
- **Endpoints**: NetSuite URLs that use an auth profile. **Create Endpoint** adds one.

## Create an auth profile

Choose **Create Auth Profile**, then answer **How should this NetSuite auth profile authenticate?**

| Auth type | What Darpan asks for |
| --- | --- |
| **None** | Nothing further. |
| **Basic** | Username and password. |
| **Bearer** | An API token. |
| **OAuth2 M2M JWT** | Token URL, **Client ID**, **Cert ID**, scopes (**RESTlets**, **REST Web Services**), and the **Private Key PEM**. |

Every profile also asks whether it is active, a label, and a name or ID.

<Note>
For OAuth 2.0, the **Client ID** comes from the NetSuite integration record and is 64 hexadecimal characters. The **Cert ID** comes from the certificate mapping and is a 43-character value. They are easy to swap; check them before saving.
</Note>

Secrets are write-only on edit: leave the password, token, or private key blank to keep the stored value.

## Create an endpoint

Choose **Create Endpoint** and answer the setup questions: the endpoint URL, the HTTP method (**POST**, **PUT**, or **GET**), the auth profile it uses, optional headers as JSON, connect and read timeouts in seconds, whether it is active, a label, and a name or ID.

## Share with another tenant

When the same NetSuite account serves several tenants, the owning tenant can share an auth profile or endpoint instead of entering the credentials again. Open the saved record and use its **Shared with** panel; see [Share the connection with another tenant](/guides/setup-shopify#share-the-connection-with-another-tenant) for how the panel works.

## Expected result

The auth profile and endpoint appear under **Open NetSuite Settings** with the labels you gave them.
