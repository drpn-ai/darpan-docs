NetSuite involves more moving parts than most connections: account IDs, role permissions, integration records, certificates. Confirming these with the NetSuite owner before you start means a failure gives you a useful error instead of a dead end.

<Note>
Runs read NetSuite over SuiteQL with an **OAuth2 M2M JWT** auth profile. A [lifecycle](/guides/lifecycle-runs) reads the account directly: you pick the account and Darpan builds its queries. A Sync run reads NetSuite through a saved NetSuite query, which defines the records to read; you can [write one from Create Run](#write-a-suiteql-query). Otherwise, export the data and use a **File upload** source when you [set up a reconciliation run](/guides/setup-reconciliation-run).
</Note>

## Before you start

Confirm:

- You are a Tenant Admin, or have edit access, for the active tenant.
- The NetSuite owner has given you the authentication method and its values: a username and password, a token, or an OAuth 2.0 client-credentials setup (client ID, certificate ID, and private key).
- For OAuth 2.0, the integration record and role in NetSuite grant the permissions the account needs.

## Open NetSuite settings

From **Ask Darpan**, open **Open NetSuite Settings**. The **NetSuite** page lists your auth profiles under **Auth**; **Create Auth Profile** adds one. Endpoints are not on this page: they live on each auth profile's details page.

## Create an auth profile

Choose **Create Auth Profile**, then answer **How should this NetSuite auth profile authenticate?**

| Auth type | What Darpan asks for |
| --- | --- |
| **None** | Nothing further. |
| **Basic** | Username and password. |
| **Bearer** | An API token. |
| **OAuth2 M2M JWT** | Token URL, **Client ID**, **Cert ID**, scopes (**RESTlets**, **REST Web Services**), and the **Private Key PEM**. |

Every profile also asks **Should this auth profile be active?** and, last, the label Darpan shows for it. Darpan gives the profile its ID; the ID cannot be edited.

<Note>
For OAuth 2.0, the **Client ID** comes from the NetSuite integration record and is 64 hexadecimal characters. The **Cert ID** comes from the certificate mapping and is a 43-character value. They are often pasted into each other's fields; check them before saving.
</Note>

Secrets are write-only on edit: leave the password, token, or private key blank to keep the stored value.

## Open an auth profile

Choose a profile under **Auth** to open its details page: its settings, the **Endpoints** that use it, and **Create Endpoint** to add one.

- **Run connection diagnostics** checks an OAuth 2.0 profile from outside the run: Darpan asks NetSuite for a token and runs a one-row SuiteQL query, then lists each check with its result. Nothing is written to NetSuite.
- **Delete NetSuite auth profile** (the trash button) removes the profile after you confirm. Darpan refuses while anything still signs in with it (an endpoint, a NetSuite query, or a saved run) and names what is in the way. Only the owning tenant can delete a profile, and only while it is not shared.

## Create an endpoint

Open the auth profile the endpoint will use, choose **Create Endpoint** under **Endpoints**, and answer the setup questions: the endpoint URL, the HTTP method (**POST**, **PUT**, or **GET**), the auth profile it uses (the one you came from is already selected), optional headers as JSON, connect and read timeouts in seconds, whether it is active, and a label. Darpan gives the endpoint its ID.

## Write a SuiteQL query

A Sync run's NetSuite side reads the records a saved query selects. When you set up the run in **Create Run**, the NetSuite config card offers **New query**; the query you save there comes back to the run you were building.

The query setup asks, one question at a time:

| Question | What you choose |
| --- | --- |
| **Which NetSuite account should this query read?** | An auth profile. |
| **What label should Darpan show for this query?** | Its name. |
| **Which record type?** | The NetSuite record type to read. |
| **Which date puts a record on a day?** | The date column the run's window applies to. |
| **Every record, or only matching ones?** | All records of that type, or only matching ones. |
| **Which records match?** | Asked only for matching ones. The rules a record must meet (**Add match rule**). |
| **Which columns should it read?** | The fields the run compares (**Add column**). |
| **Which field is the key?** | The field that matches a NetSuite record to the other side. |
| **Preview, then save.** | Pick a day and choose **Preview** to see the first rows NetSuite returns and the SuiteQL Darpan sent. Nothing is saved until you save. |

## Import existing NetSuite checks

If the tenant already has NetSuite checks, Home shows **Import NetSuite Checks** beside **Create Run** to users who can edit the tenant. It turns the checks into runs in one step and reports how many it imported and skipped, with the reason for each skip. Running it again adds only checks that are not yet in a run.

## Share with another tenant

When the same NetSuite account serves several tenants, the owning tenant can share an auth profile or endpoint instead of entering the credentials again. Open the saved record and use its **Shared with** panel; see [Share the connection with another tenant](/guides/setup-shopify#share-the-connection-with-another-tenant) for how the panel works.

## Expected result

The auth profile appears under **Auth** on the **NetSuite** page with the label you gave it, and its endpoints appear under **Endpoints** on the profile's details page.

## Troubleshooting

Run the diagnostics on the auth profile first. [Connections troubleshooting](/troubleshooting/connections#netsuite) lists each failed check and its fix, including a **Client ID** and **Cert ID** pasted into each other's fields.
