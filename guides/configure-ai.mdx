---
title: "AI provider settings"
description: "What the AI provider settings store, and what they do not do yet."
---

Tenant Settings has an **AI Configuration** section. It stores AI provider settings. No Darpan feature reads these settings yet: schema inference, matching, rules, and results all work without them, and saving a provider changes nothing about how a run behaves.

This page describes what the section stores, so the record is accurate if you keep one.

## Who can edit it

Only a Darpan admin (the DARPAN_ADMIN group) can view or change the section. Tenant Admins see **Darpan admin only** in its place.

## What is stored

From **Ask Darpan**, open **Open Tenant Settings** (it also matches ai, llm, and api key), then choose the **AI Configuration** tile.

| Field | Notes |
| --- | --- |
| **Provider** | **OpenAI** or **Gemini**. One provider is the selected one at a time. |
| **Enabled** | **Yes** or **No**. |
| **Model** | The model name, for example `gpt-4.1-mini`. |
| **Timeout (seconds)** | Request timeout for the provider. |
| **Base URL** | The provider's API base URL. Only `api.openai.com` and `generativelanguage.googleapis.com` are accepted; leave it blank to keep the provider default. |
| **API Key** | The raw provider key. Leave it blank on edit to keep the stored key. |

The same settings are available through `facade.SettingsFacadeServices.get#LlmSettings` and `save#LlmSettings`.

## Safety

The API key is a live credential. Use a key scoped for this purpose, and do not paste one you would not want stored. Because nothing uses the settings yet, leaving the section unconfigured costs nothing.
