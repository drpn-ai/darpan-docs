---
title: "Set up an automation"
description: "Create a scheduled automation for a saved reconciliation run, or run one on demand."
---

An automation puts a reconciliation run on a schedule — or makes it available on demand — so you are not manually running the same comparison every day. Set the input source and cadence once; Darpan handles execution and alerts from then on.

## Before you start

Confirm:

- A saved reconciliation run exists, or you are ready to create one.
- The saved run has the correct source systems, schemas, and primary IDs.
- Source access is ready: SFTP servers for file inputs, or API sources such as Shopify and HotWax for date-range extraction.
- The schedule is known: hourly, daily, weekly, or monthly. You can also run an automation on demand, and pause it with its **Active**/**Inactive** status.
- The remote file paths or API date window are known.
- The tenant timezone is set. A new automation takes the tenant's zone when it is saved.
- Your user can edit tenant settings.

## Automation choices

| Choice | Use when |
| --- | --- |
| **Automate an existing reconciliation** | The saved run already exists and only needs input and schedule setup. |
| **Create a new reconciliation and automate it** | The saved run needs to be created before automation can be saved. |
| **SFTP scheduled file pickup** | Each run should read files from SFTP paths. |
| **API extraction** | Each run should pull source records from API-backed sources such as Shopify or HotWax for a date window. |
| **Run now** or the **Active**/**Inactive** status | The automation should be runnable on demand, or paused, instead of relying only on its schedule. |
| **Daily**, **Hourly**, **Weekly**, or **Monthly** | The automation should run on a recurring schedule. **Daily**, **Weekly**, and **Monthly** also take a **Time** (defaults to 06:00); **Hourly** takes a **Minute**. |

## Steps

<Steps>
<Step title="Open automations">

Open **Ask Darpan** with `Cmd/Ctrl+K` or by clicking the mascot in the corner. Search for **Open Automations** and open the result.

</Step>
<Step title="Start the automation wizard">

Choose **Create Automation**. Darpan asks **What is this automation for?**

Choose **Automate an existing reconciliation** when the saved run already exists. Choose **Create a new reconciliation and automate it** when the run setup still needs to be created.

</Step>
<Step title="Choose the saved run">

When Darpan asks **Which saved run should this automation use?**, select the saved reconciliation run.

If the run is missing, go back to [Set up a reconciliation run](/guides/setup-reconciliation-run) and create it first.

</Step>
<Step title="Choose the input mode">

When Darpan asks **How will Darpan get source data for …?**, choose one input mode:

- **SFTP scheduled file pickup** for two remote file paths.
- **API extraction** for two API-backed sources and a date window.

If the saved run uses only API sources, Darpan picks **API extraction** for you and skips the question.

</Step>
<Step title="Configure the sources">

For **SFTP scheduled file pickup**, choose the SFTP server for the first file, enter the first remote path, choose the SFTP server for the second file, and enter the second remote path.

For **API extraction**, choose the API source for each side when there is more than one, then answer **How far back should each scheduled run reconcile?** with a window such as **Previous day**, **Last N days**, or **Custom range**.

</Step>
<Step title="Choose the schedule">

When Darpan asks **When should Darpan run this automation?**, choose **Daily**, **Hourly**, **Weekly**, or **Monthly**. **Weekly** adds a **Day**, **Monthly** adds a **Date**, and **Daily**, **Weekly**, and **Monthly** take a **Time**, which defaults to 06:00. **Hourly** takes a **Minute**.

An automation whose schedule matches none of the presets, for example one saved through the API, shows **Custom schedule** and keeps that schedule until you pick a preset.

The schedule shows the **Timezone** it runs in, and you can pick another. See [Timezone](#timezone) below before relying on a specific hour.

To run an automation on demand, use **Run automation now** on its dashboard. To stop scheduled runs without deleting the automation, switch the **Active**/**Inactive** toggle on its dashboard, so pausing one does not mean opening its edit form.

</Step>
<Step title="Choose where notifications go">

When Darpan asks **Where should Darpan send notifications for this automation?**, choose your default space, **Choose another space**, **Set up a new space**, or **No notifications**. A new space asks for a name, the chat product (**Google Chat** or **Slack**), and a webhook URL or Slack channel. Only the active tenant's own chat spaces are offered, and the backend refuses an automation pointed at another tenant's space. See [Run-completion alerts](/guides/run-completion-alerts).

</Step>
<Step title="Name and create the automation">

Answer **What should this automation be called?** with a stable name that includes the compared systems and cadence. Choose **Create Automation**.

</Step>
<Step title="Validate the automation">

Return to **Open Automations** and open the automation tile to view its dashboard. Confirm the **Schedule**, **Window**, and **Next Run** are as expected.

Use the **Run automation now** action (the play icon) for a controlled test, then check **Previous Runs** for the execution status and differences.

</Step>
</Steps>

## Timezone

Each automation stores its own timezone, and its schedule and date window run in that zone. The schedule's **Timezone** shows which one.

- A new automation takes the **tenant's timezone** when it is saved (UTC if the tenant has none), and keeps it.
- Changing the tenant timezone later does **not** move existing automations. They keep running in the zone they were saved with.
- A zone that does not match the tenant's business day reconciles the wrong day: a daily window of "previous day" ends at midnight in the automation's zone, not the tenant's.

To correct a wrong zone, edit the automation and pick the right one in **Timezone** on the schedule card. An edit you leave untouched saves the zone it loaded, so opening and saving an automation never moves it. Do not work around a wrong zone by shifting the clock hour: the window boundaries stay in the old zone.

## Delete an automation

The trash icon on an automation's dashboard, **Delete automation**, archives the automation. It asks for confirmation, leaves the automation list, and never fires again, scheduled or otherwise. Nothing is deleted: its source setup and execution history stay. The app has no control to bring it back; `facade.ReconciliationFacadeServices.restore#Automation` restores it with its history intact.

To stop it running for a while and keep it on the list, set it **Inactive** instead.

## Keep an automation in step with its run

An automation is a **snapshot** of a saved run, not a live pointer at one. It copies the compare scope, the input mode, both source definitions and the exclusion filters at the moment you create it. Editing the underlying run afterwards does not change the automation — which is deliberate, since a nightly job silently changing shape because someone edited a run during the day is worse than one that stays put.

The cost of that choice is drift. So Darpan reports it: open an automation whose saved run has moved on and it names the fields that no longer match.

**Sync** re-derives the snapshot from the saved run. It overwrites the compare scope, the input mode, both source definitions and the exclusion filters. It preserves everything the run cannot supply — the name, the schedule, the window, the chat space, the active status, and the SFTP server, path and pattern.

<Note>
Sync never re-points an automation at a different run. The saved run an automation was built from is fixed for its lifetime: **an automation's saved run cannot be changed — create a new automation for a different run.** If the saved run has been deleted, sync refuses rather than guessing, and the automation has to be recreated.
</Note>

Sync when the drift report names a field you care about. Ignore it when it names one you deliberately diverged from — the automation is allowed to differ from its run, and Darpan reports the difference rather than correcting it for you.

## Troubleshooting

- If no saved runs appear, finish [Set up a reconciliation run](/guides/setup-reconciliation-run) first.
- If an automation reports drift, compare the named fields against the saved run and use **Sync** only if you want the run's version to win.
- If **Sync** is refused, the automation's saved run no longer exists. Recreate the automation against a current run.
- If a schedule fires at an unexpected hour, or reconciles the wrong day, check the **Timezone** shown on the automation's schedule. It is the zone the automation was saved with, which may no longer match the tenant's. Correct it in the edit form. See [Timezone](#timezone).
- If saving or syncing is refused with a view-access message, your active tenant grants you view access only; automation changes need write access.
- If no SFTP source appears, create or reactivate the required SFTP server from **Open SFTP Servers**.
- If no API source appears, confirm the relevant system setup from [Set up Shopify](/guides/setup-shopify) or [Set up HotWax](/guides/setup-hotwax).
- If a scheduled automation produces no matches, check source date ranges, remote file paths, schemas, and primary IDs before changing the schedule.
