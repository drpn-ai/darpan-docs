title: "Set up HotWax"
description: "Create the HotWax connection used by API-backed reconciliation runs and automations."
---

HotWax setup is a one-time task — save the connection once and every reconciliation run or automation that reads HotWax order data can use it from then on.

<Note>
Keep passwords, JWT bearer tokens, API keys, customer hostnames, and account-specific values in secure configuration. The docs should describe the sequence, not store credentials.
</Note>

## Before you start

Confirm:

- You are signed in to the correct active company or active tenant.
- Your user can edit connection settings.
- The HotWax Moqui API URL is known.
- The HotWax authentication type is known: none, basic, bearer, or API key.
- The required username, password, JWT bearer token, or API key is available in secure configuration.
- You know which HotWax data you will reconcile: orders, transfer orders, or returns.

## Steps

<Steps>
<Step title="Open HotWax settings">

Open **Ask Darpan** with `Cmd/Ctrl+K` or by clicking Tara, the red panda in the corner. Search for **Open HotWax Settings** and open the result.

</Step>
<Step title="Create the HotWax connection">

Choose **Create Auth Profile**. Answer the setup questions:

1. **Base URL**: use the HotWax Moqui API URL, not the storefront, admin app, or another system URL
2. **Timezone**: which timezone Darpan should use for HotWax date windows
3. **Auth Type**
4. Username and password for basic auth, a JWT token retrieved from HotWax when **Bearer** is selected, or an API key when the auth type requires it
5. HotWax label

For bearer authentication, use the JWT token value from HotWax. Darpan sends it as the HTTP `Authorization: Bearer <jwt-token>` header.

Save the connection. Darpan creates it as active and derives the connection ID from the label. If the ID, active state, auth details, or endpoint access needs to change later, open the saved connection from **Open HotWax Settings** and edit it.

The edit form also carries **Available Endpoints**, where you choose which endpoints this connection may be read through, and the **Shared with** panel. See [Share the connection with another tenant](/guides/setup-shopify#share-the-connection-with-another-tenant).

</Step>
<Step title="Confirm the connection is reusable">

Return to **Open HotWax Settings**. The saved connection should appear on the settings surface.

The connection is ready when a reconciliation run or automation can select HotWax as an API source.

</Step>
</Steps>

## Endpoints

One HotWax connection can serve several endpoints, because they share the same base URL and credentials:

| Endpoint | Reads |
| --- | --- |
| **Orders** | Sales orders, over the REST orders API. |
| **Orders and payments** | Sales orders with payment fields, over GraphQL. |
| **Sales orders** | Sales orders, served with a fixed set of fields. Use **Orders** when your rules need fields outside that set. |
| **Transfer orders** | Transfer orders, from the same orders API. |
| **Order lines** | One record per order-line unit, so a quantity shortfall on a line is visible. No point lookup. |
| **Order lines (NetSuite)** | Order items for NetSuite line-level checks. Items without a Shopify line ID are kept. |
| **Refunded returns** | Returns, over REST. Sees refunded returns only. For [returns reconciliation](/guides/returns-and-exchanges). |
| **Returns** | Returns, over GraphQL, including pending returns. Slower than **Refunded returns**. Needs the HotWax GraphQL upgrade; without it the extract fails rather than returning an empty file. |

Run pickers and results name these by source: **HotWax refunded returns**, **HotWax returns**, **HotWax orders and payments**, **HotWax order lines**, and so on. **Returns** mirrors **Refunded returns** field for field, so moving a returns run to GraphQL is a source switch.

Each connection enables endpoints separately under **Available Endpoints**. An endpoint that is not enabled is not offered when you build a run. The saved connection's page lists the enabled endpoints under **Endpoints**.

## Validation

Open the saved connection from **Open HotWax Settings** and choose **Run connection diagnostics**. Darpan checks the base URL and credentials and lists each check with its result, without running a reconciliation.

Then run one small reconciliation with a narrow date range and confirm HotWax returns records before you schedule it.

## Troubleshooting

- If HotWax fails, run the connection diagnostics first, then check the Moqui API URL, auth type, bearer token validity, API key header behavior, and tenant context.
- If HotWax does not appear as an API source, confirm the connection is active and that the endpoint you need is enabled under **Available Endpoints**.
- If the request succeeds but returns no records, test a wider date range and confirm the tenant has orders for that period.
