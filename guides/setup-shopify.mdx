---
title: "Set up Shopify"
description: "Create the Shopify connection used by API-backed reconciliation runs and automations."
---

Shopify setup is a one-time task — save the connection once and every reconciliation run or automation that reads Shopify order data can use it from then on.

<Note>
Keep access tokens, customer hostnames, and account-specific values in secure configuration. The docs should describe the sequence, not store credentials.
</Note>

## Before you start

Confirm:

- You are signed in to the correct active company or active tenant.
- Your user can edit connection settings.
- The Shopify shop or Admin API URL is known.
- The Shopify API version is known.
- The timezone for Shopify date windows is known.
- The Shopify access token can read orders, and returns if you will reconcile returns. Without `read_all_orders`, Shopify only serves orders from the last 60 days.

## Steps

<Steps>
<Step title="Open Shopify settings">

Open **Ask Darpan** with `Cmd/Ctrl+K` or the floating **Ask Darpan** button. Search for **Open Shopify Settings** and open the result.

</Step>
<Step title="Create the Shopify connection">

Choose **Create Shopify Config**. Answer the setup questions:

1. **Shop/API URL**
2. **API Version**
3. Timezone
4. **Access Token**
5. Shopify label

Save the connection. Darpan creates it as active and derives the connection ID from the label. If the ID, active state, or endpoint access needs to change later, open the saved connection from **Open Shopify Settings** and edit it.

The edit form also carries **Available Endpoints**, where you choose which endpoints this connection may be read through, and the **Shared with** panel.

</Step>
<Step title="Confirm the connection is reusable">

Return to **Open Shopify Settings**. The saved connection should appear on the settings surface.

The connection is ready when a reconciliation run or automation can select Shopify as an API source.

</Step>
</Steps>

## Endpoints

| Endpoint | Reads |
| --- | --- |
| **Admin GraphQL Orders** | Orders, for order reconciliation. |
| **Shopify Return References** | One record per refund or return, for [returns reconciliation](/guides/returns-and-exchanges). |

Each connection enables endpoints separately under **Available Endpoints**. An endpoint that is not enabled is not offered when you build a run. The saved connection's page lists the enabled endpoints under **Endpoints**.

## Validation

Open the saved connection from **Open Shopify Settings** and choose **Run connection diagnostics**. Darpan checks the credentials against Shopify and lists each check with its result, without running a reconciliation.

Then run one small reconciliation with a narrow date range and confirm Shopify returns records before you schedule it.

## Share the connection with another tenant

An organisation running several tenants against one upstream system would otherwise enter, rotate and audit the same credentials in each. Sharing removes the duplication: one tenant owns the connection, and named peer tenants may use it.

Open the saved connection's edit form. The **Shared with** panel shows the owning tenant, marked **owner**, and a chip for each peer tenant.

- **+ Add tenant** opens a picker of tenants you can share with. Choosing one grants it access.
- The × on a peer chip revokes that tenant's access. The chip turns into **… removed** with an **undo** link for a few seconds.

Only a Tenant Admin (or a Super Admin) can change sharing. Peers use the connection; they do not take it over, and the credential itself is never shown to them. Revoking access stops runs in that tenant from resolving the source, so check which of its runs depend on it first.

The same panel appears on HotWax connections and on NetSuite auth profiles and endpoints.


## Troubleshooting

- If Shopify fails, run the connection diagnostics first, then check the shop URL, API version, token validity, and order-read permission.
- If Shopify does not appear as an API source, confirm the connection is active and that the endpoint you need is enabled under **Available Endpoints**.
- If records return outside the expected window, confirm the timezone used for Shopify date windows.
