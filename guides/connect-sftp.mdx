---
title: "Connect SFTP"
description: "Create or maintain an SFTP connection record."
---

An SFTP connection is a one-time record — set it up once and every run or automation that needs files from that server can use it without re-entering credentials.

## Before you start

Confirm these values with the server owner:

- Host and port
- Username
- Password, private key, or both
- The remote folders and file paths runs will read from

## Create the connection

From **Ask Darpan**, open **Open SFTP Servers**, then choose **Create New Server**. Darpan asks one question per card:

| Field | Notes |
| --- | --- |
| Host | The server hostname, for example `sftp.example.com`. |
| Port | The SFTP port. |
| Username | The login name on the server. |
| Remote attributes | **Yes** or **No**. Defaults to **Yes**; change it only when the server owner says the server needs it. |
| Password | Optional. Leave blank when the server uses a key. |
| Private key | Optional. Paste the private key when the server uses key authentication. |
| Label | The name Darpan shows for this server. |
| Server name / ID | A stable ID for the record, for example `primary_sftp`. |

Save the record. Passwords and keys are write-only: on edit, leave them blank to keep the stored values.

## Edit an existing connection

1. Open **Ask Darpan**.
2. Search for the SFTP description, host, or username.
3. Select the **Edit SFTP: ...** result.
4. Update the record and save it.

## Validation

After saving, create a test automation with **SFTP scheduled file pickup** that reads a known file from the server, and use **Run automation now**. If it fails, check the remote path, the password or key, and whether the Darpan deployment can reach the host.

<Warning>
Private keys, passwords, and customer hostnames belong in secure configuration, not public docs.
</Warning>

## Expected result

The connection appears in **Open SFTP Servers** and can be selected by any reconciliation run or automation that reads from or writes to that server.
