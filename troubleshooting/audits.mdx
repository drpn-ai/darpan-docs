title: "Audits and findings"
description: "Troubleshoot audits that did not run, checks that did not run, findings that stay open or are missing, refused acknowledgements and re-checks, and updates that did not arrive."
---

When an audit looks wrong, the cause is usually one of a few things: the schedule is off, a check did not run, or a finding is listed somewhere you did not expect. The audit page keeps the evidence for each, and most fixes take one choice. Find your symptom below.

For how audits work, see [Audits](/guides/audits).

## The audit did not run this morning

- **Daily is off.** A new audit's schedule starts off, set to 06:00 in the tenant's time zone. Open the gear (**Audit settings**) and turn **Daily schedule** on.
- **Its automations were changed one by one.** The audit owns its schedule. The automations behind its checks show **Set by audit** *name* under **Schedule** and follow the audit's **Daily schedule**, time, and timezone. Change the schedule in **Audit settings**, not on an automation.
- **It is not due yet.** Before the audit's scheduled time, the page shows yesterday's morning, the last one that was due. Today's shows once the scheduled time passes or a check runs today.
- **The run is waiting.** Audit runs wait in a queue when the instance is busy. **Run health** shows **Queued**, or **Queued · retry, attempt** *N* when a failed run is trying again. A queued run starts on its own. See [the run queue](/reference/reconciliation-runs#run-queue).

To run it now, choose the play icon (**Run audit**) beside the audit's name.

## A check did not run

**Run health** says how many checks ran and whether each system's read was complete. A complete morning reads "Every configured check ran over complete reads." Otherwise it names what is missing, for example "Not complete: the *system* read was partial; check *code* did not run." In the statement's detail, each check shows **Ran**, **Partial**, or **Not run**.

On today's report, choose **Retry from last read** on the check. It runs again from what that morning's run already read, so no system is read again. **Retry** *N* **not run** retries every check that did not run. These retries are offered on today's report only.

| Darpan says | What to do |
| --- | --- |
| "Check *code* already ran on *date*." | Nothing to retry. Refresh the page to see its result. |
| "Check *code* has no run on *date* to retry from; play the audit instead." | That morning's run never read anything for this check. Choose **Run audit**. |
| "… did not finish reading *system*, so there is no complete extract to retry from; run it again instead." | A read stopped part way, so there is nothing complete to retry from. Choose **Run audit**. |

A check is **Not run** when one side of its run read no records, or kept none after its filters, while the other side read some. Its reason says which, for example "The *side* side read no records." or "The *side* side kept 0 of *N* records." Nothing closes that morning, and Darpan is alerted. Check that side's connection and filters, then play the audit again.

A check marked **Partial** ran over a read that was not complete, so it may have missed records. Play the audit again once the system is reachable.

When **Partial** says "Older findings were not re-checked:" and a reason, the check could not read its older open findings again by key. They keep the day they were last checked until a read can reach them. A HotWax returns side matched on the return's Shopify order id is read this way from 3.4.5, so its older findings are re-checked each morning.

When **Partial** says "Records changed since the last read were not re-read:" and a reason, the check could not read the HotWax orders that changed since its last read. Orders completed after they were placed may not show as completed until a later run reads them.

## A check stopped running after an import

A check that an import or a restored config version took off its last statement no longer runs. Before this release it kept running every morning, recorded nothing, and logged "Audit check *id* tests no statement". Now it is skipped, its automation runs any other checks it carries, and nothing is lost: it had no statement to report a finding to.

If the unlink was on purpose, nothing needs doing. If it was not, link the check to a statement again with a config import, or restore the config version from before it. See [A check on no statement](/guides/audits#a-check-on-no-statement).

## A statement says Not covered

No check tests the statement yet, so it cannot have findings. **Run health** lists these statements. In **Audit settings**, open the statement and choose **Add check**.

## A finding stays open after you fixed it

A fix counts when a check sees it, not when someone says so. Each morning run re-checks open findings by key, so a record fixed in its own system closes on the next run.

To check one finding now, open it and choose **Resolve finding**. Darpan reads that record from each system by key.

| Darpan says | Meaning |
| --- | --- |
| **Resolved. The finding is closed.** | The check no longer sees the problem. |
| **Still open. The cause above is from this check.** | The problem is still there. The cause shown is from this check, so read it again: the fix may be in a different system than you expected. |
| "Finding *id* cannot be re-checked: its check has no automation yet (play the audit once)." | The check has never run. Choose **Run audit** once, then try again. |

There is no control that marks a finding fixed by hand. Resolve does not count as a check run, so **Run health** does not change.

When many findings were fixed after the morning check, choose **Re-check all findings** instead: beside the audit's name for the whole period, or at the head of the **Findings** column for one statement. It reads each check's open findings once, by key.

| Darpan says | Meaning |
| --- | --- |
| **Re-checked** *N*. *X* **closed,** *Y* **still open.** | Every finding was read again. The ones still open still have the problem; read each one's cause. |
| **Nothing open to re-check.** | No finding is open in this period, or under this statement. |
| **Nothing to re-check until the audit has run once.** | The checks behind these findings have never run. Choose **Run audit** once, then try again. |
| *N* **closed so far. The rest are still being checked.** | The reads took longer than the 5 minutes the page waits. They finish on their own; reload the page later. |
| **The re-check did not start. Try again.** | Choose the icon again. If it keeps failing, use **Resolve finding** on the findings that matter most. |

**Re-check all findings** is in the app only. From the CLI, re-check one finding at a time with `darpan findings recheck`.

## A finding you expected is not listed

- **It is listed under an earlier statement.** An order with findings under several statements counts once, under its earliest statement. Open that finding and look under **Also on this order**. The later statement's counts say how many sit **under an earlier step**.
- **The board is filtered.** **open** lists only statements with open findings no one has acknowledged, **acknowledged** only those someone has, and **not checked** only statements whose checks did not run. Choose **all** to list every statement.
- **Someone acknowledged it.** An acknowledged finding leaves **open** and is listed under **acknowledged**, with who acknowledged it and the note. Choose **Reopen** on its card to put it back. See [Acknowledge a finding](/guides/audits#acknowledge-a-finding).
- **The statement is turned off.** A statement turned off in **Audit settings** is left out of runs. Its earlier findings stay on record.
- **The check has not run for that day.** See [A check did not run](#a-check-did-not-run).

A new finding is **Open** from the run that finds it. Findings are either **Open** or **Fixed**; there is no waiting period before one is listed. **Acknowledged** is not a third state: an acknowledged finding is still open, set aside with a note.

## An acknowledged finding is back on open

- **Its reminder day came.** With **Remind me in 5 days if still open** on, a finding still open after that day is back under **open**, and its card says, for example, **Acknowledged 5 days ago by Sam R., still open**. Acknowledge it again to start a fresh reminder, or fix it.
- **Another line of the order broke.** An acknowledgement covers the lines that were open when it was made. A line of the same order that breaks later is a new problem, so the row is back under **open**.
- **It was fixed and found again.** An acknowledgement does not carry over a fix. A finding that closes and is found again on a later morning is plainly open.

## An acknowledgement is refused

| Darpan says | What to do |
| --- | --- |
| "Only an open finding can be acknowledged" | A check closed the finding after you opened it. Reload the page. |
| "Add a note" | An acknowledgement needs a note saying why the finding is known. |
| "Keep the note under 4,000 characters" | Shorten the note. The same limit applies to feedback. |
| **Reopen did not go through. Try again.** | Choose **Reopen** again. |
| **The note did not send. Try again.** | Your feedback did not reach Darpan. Choose **Send** again. |

## A cause is not listed under a statement

**Audit settings** list under a statement only the causes its checks can reach. When several statements' checks share one run, a cause for missing records shows under the statement whose check looks for missing records, and a rule's cause under the statement that checks field mismatches. To set a cause's priority, open the statement that lists it. A priority saved earlier on a cause the statement cannot reach still shows there, so you can set it back to **Same as**.

## The update after a run did not arrive

- **After each run is off.** Open **Audit settings**, choose **After each run**, and turn it on. Only a Tenant Admin can change it; for everyone else it does not open.
- **No chat message.** The chat space must still exist, belong to this tenant, be active, and have a webhook or Slack channel. Otherwise the run sends no chat message, and **Audit settings** says why under the audit's name: **This chat space no longer exists, so no card is sent.**, **This chat space is turned off, so no card is sent.**, or **This chat space has no webhook or Slack channel, so no card is sent.** Choose **Posts to** and pick a space again, or fix the space in **Tenant Settings** under **Notifications**.
- **No email.** The update goes to the people with access to the tenant, plus any address under **Also send to**. Email needs the Darpan instance to be able to send mail. If **Forgot password?** does not appear on the sign-in page, the instance cannot send email; ask a Darpan admin.

## A report link opens a different tenant

A link in the update after a run names the tenant it belongs to, and opening it switches the app into that tenant. If you then work in another tab, check the tenant shown there: the active tenant is shared by every tab. See [Login and session](/troubleshooting/login-and-session#records-changed-after-you-switched-tenant-in-another-tab).

## The Agent tab is missing

The **Agent** tab appears only when the agent is on for your tenant, you are a Tenant admin or Company editor there, and a Darpan admin has given you AI access. A Tenant user or Company view only member does not get the tab, and a call to the agent is refused with "Only editors and tenant admins can talk to the agent." Ask a Darpan admin for the role or the access you are missing. See [Auth and access](/reference/auth-and-access#ai-access).

## Play, Retry, Resolve or Re-check all is missing

Running an audit, retrying a check, **Resolve finding** and **Re-check all findings** need a role that can run in the tenant: Tenant user, Company editor or Tenant admin. A Company view only member reads the audit without them, and can still acknowledge a finding and send Darpan feedback on one.

## Saving an audit is refused

| Darpan says | What to do |
| --- | --- |
| "There is already an audit by that name." | Choose another name. |
| "Name the audit with a letter or a digit." | The name needs at least one letter or digit. |
| "Call the audit something other than new." | `new` is reserved. Choose another name. |
| "Say what must be true." | A statement cannot be empty. Write what must hold, such as "every shipped order is invoiced". |
| "Audit *code* was not found" | No audit with that code exists in the active tenant. Check the active tenant in **User Settings**. |
| "Finding *id* was not found" | The finding belongs to another tenant, or the link is out of date. Check the active tenant. |
